# 数据字典（A 股日线 / 分钟线）

- **版本**：v1
- **状态**：Accepted
- **适用**：行情落地、策略读取、回测与实盘共用的统一数据契约
- **相关**：`docs/adr/0001-architecture-style.md`（Parquet + DuckDB 存储）

本文定义系统内**唯一**的行情数据契约。任何模块（采集、回测、模拟盘、实盘、报表）读写行情都必须遵循本文，不得私自定义字段或时间语义。

---

## 1. 核心字段定义

行情表按 `(symbol, freq)` 分区存储，每行为一个 bar。

| 字段 | 类型 | 单位 | 含义 |
| --- | --- | --- | --- |
| `symbol` | string | — | 标的唯一代码，格式 `代码.交易所`，交易所后缀为 `SH` / `SZ` / `BJ`，如 `600519.SH`、`000001.SZ`、`430047.BJ`。全库统一为大写，不接受 `sh600519`、`600519` 等变体。 |
| `timestamp` | datetime64[ns] | — | bar 的**开始时间**（左标签，见 §4.2），时区 `Asia/Shanghai`，不带 UTC 偏移存储，但语义上属于该时区。日线为当日 `09:30`。 |
| `open` | float64 | 元/股 | 该 bar 内第一笔成交价。日线为集合竞价后的开盘价。 |
| `high` | float64 | 元/股 | 该 bar 内最高成交价。 |
| `low` | float64 | 元/股 | 该 bar 内最低成交价。 |
| `close` | float64 | 元/股 | 该 bar 内最后一笔成交价。日线为收盘价（含收盘集合竞价）。 |
| `volume` | float64 | **股**（规范层） | 该 bar 内成交量。规范层统一用「股」，1 手 = 100 股。原始层列名为 `vol`、单位是「手」，换算见 §1.4。 |
| `amount` | float64 | **元**（规范层） | 该 bar 内成交金额。规范层统一用「元」。原始层同名列单位是「千元」，换算见 §1.4。 |

### 1.1 价格字段的复权状态

`open/high/low/close` 的**存储值一律为不复权价**（见 §2）。复权在读取层按视图计算，不落盘。因此字段本身不带复权标记；调用方必须通过查询参数显式指定复权方式，默认值为 `qfq`。

### 1.2 可选辅助字段（随分区一并存储）

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `trade_date` | date | 交易日，用于按日分区与 join，避免对 `timestamp` 做时区转换后再取日期。 |
| `available_at` | datetime | 该 bar 完整可用的时刻（日线当日 15:00，分钟线 `timestamp + freq`），as-of 断言唯一依赖的时间量，见 §4.2。 |
| `is_suspended` | bool | 该 bar 是否为停牌占位行（见 §3）。正常成交为 `False`。 |
| `limit_up` / `limit_down` | float64 | 该 bar 对应交易日的涨跌停价（不复权口径），供撮合层判断可成交性。 |

### 1.3 精度与空值约定

- 价格保留交易所公布的小数位（A 股 2 位），不做额外四舍五入。
- 数值字段**不使用 `0` 表示缺失**。缺失即 `null`（Parquet 的 NULL），由查询层显式处理（见 §3）。
- `volume` / `amount` 为 0 且 `open/high/low/close` 均为 `null` 的行，表示「当日无成交」，不表示「成交量为零的正常 bar」。

### 1.4 两套单位：原始层与规范层

数据在系统内有**两个单位口径**，边界只有一处：`storage.to_canonical()`。跨过这条线之前，一律是原始层；跨过之后，一律是规范层。**中间层不得再做任何换算。**

| | 原始层（落盘） | 规范层（策略/回测/指标） |
| --- | --- | --- |
| 存放位置 | `data/raw/daily/trade_date=YYYYMMDD/data.parquet` | 内存中的 DataFrame，不落盘 |
| 成交量列名 | `vol` | `volume` |
| 成交量单位 | **手**（Tushare 原样） | **股** |
| 成交额列名 | `amount` | `amount` |
| 成交额单位 | **千元**（Tushare 原样） | **元** |
| 价格 | 元/股，不复权 | 元/股，不复权 |
| 生成方式 | `storage.save_daily()` 原样写入 | `storage.to_canonical(df)` |

换算关系（唯一实现，不要在其他地方重写）：

```
volume(股) = vol(手) × 100
amount(元) = amount(千元) × 1000
```

约定与理由：

1. **落盘保持供应商原样**，不做任何单位加工。好处是回查原始数据、和接口返回值逐字段比对时不会引入二次误差，也避免了「不知道这份 Parquet 到底换算过没有」的隐患。
2. **换算集中在读取层一次完成**。同一个换算写两遍就会出现 100 倍或 1000 倍的错，而且这种错误在回测里表现为「收益率正确、换手率离谱」，极难察觉。
3. **列名不同是故意的**：原始层叫 `vol`，规范层叫 `volume`，让混用立刻报 `KeyError`，而不是静默算错。唯一例外是 `amount` 两层同名但单位不同（千元 / 元），使用时必须确认数据是否已过 `to_canonical()`。
4. **校验口径**：任一 bar 满足 `amount(元) ÷ volume(股) ≈ close`，偏差应在合理滑点内。这是判断单位有没有搞错最快的自检。

## 2. 复权规则

### 2.1 三种口径的适用场景

| 口径 | 定义 | 使用场景 | 禁止使用场景 |
| --- | --- | --- | --- |
| **不复权（raw / none）** | 交易所原始成交价，除权日价格会跳空。 | ① 存储层唯一口径；② 撮合与成本计算（真实成交价、佣金、印花税、滑点）；③ 涨跌停价判断；④ 与券商对账单核对。 | 计算跨除权日的收益率、均线、动量等价格序列指标。 |
| **前复权（qfq）** | 以**当前最新**价格为基准，向前调整历史价格，使最新价等于真实价。 | ① 策略信号计算（均线、突破、动量等）；② 可视化看盘；③ 回测中的指标与信号生成。 | ① 撮合与资金结算；② 结果存档复用（基准日会变，见 2.3）。 |
| **后复权（hfq）** | 以上市首日为基准，向后调整，历史价不变、最新价被放大。 | ① 长周期收益归因与绩效统计；② 需要「同一价格序列永久可比」的因子研究。 | ① 展示给用户看盘（价格失真，与实盘价不符）；② 撮合成交。 |

### 2.2 存储采用哪种

**存储层只存不复权价 + 复权因子，不存任何复权后的价格。**

具体结构：

1. 行情分区存 `open/high/low/close/vol/amount`，全部为不复权原始值、原始单位（手 / 千元）。
2. 单独维护 `adj_factor` 表：`symbol`、`trade_date`、`factor`（累积复权因子），除权除息日更新。
3. 查询层提供 `adjust` 参数（`none` / `qfq` / `hfq`），在 DuckDB 查询时用因子实时计算，结果不落盘。

理由：前复权价格随最新除权事件变化，一旦落盘，历史回测结果就无法复现，直接违反 PRD 中「相同数据 + 相同参数运行两次结果一致」的验收项。存因子是唯一能同时满足可复现与多口径的方案。

### 2.3 前复权的基准日约束

- 前复权计算必须显式指定 `base_date`（默认 = 数据集中最后一个交易日）。
- **回测中禁止使用「今天」作为基准日**：应使用回测区间结束日，否则每次运行会因新的除权事件产生不同结果。
- 回测报告须记录 `base_date`，作为复现条件之一。

## 3. 停牌处理

### 3.1 表示方式

停牌期间**不生成正常 bar，也不以前收盘价填充价格序列**。

| 场景 | 落地方式 |
| --- | --- |
| 全天停牌 | 该 `trade_date` 不生成行情行。若需保留交易日历完整性，可生成一行占位：`open/high/low/close = null`、`volume = 0`、`amount = 0`、`is_suspended = true`。默认**不生成**，由交易日历表负责「哪些日子存在」的问题。 |
| 盘中临时停牌（分钟线） | 停牌时段不生成 bar；当日已成交时段的 bar 正常保留。 |
| 停牌期间除权 | `adj_factor` 仍按公告更新，行情行缺失不影响因子表连续性。 |

**为什么不用前收盘价填充**：填充会把「无成交」伪装成「成交量为零的平价 bar」，策略无法区分「停牌」与「一字板缩量」，且填充价可能被撮合层误判为可成交价，制造出实盘不可能出现的成交。

### 3.2 策略读取时应该如何处理

策略层拿到的是**可能缺失 bar 的序列**，必须按下述规则处理：

1. **判断可用性**：以交易日历为基准左连接行情，缺失即视为停牌。策略不得假设「每个交易日都有一根 bar」。
2. **指标计算**：允许对价格做 `ffill`（前值填充）以维持指标窗口长度，但**必须用单独的 `is_tradable` 掩码**标记该日不可交易。填充只用于计算，不用于生成订单。
3. **信号与下单**：`is_tradable == False` 的 bar 上，**禁止产生新开仓信号，禁止撮合成交**。已持仓的止损/止盈条件可继续评估，但只能在复牌后首个可交易 bar 执行。
4. **复牌首日**：复牌首日按真实开盘价撮合，不继承停牌前的挂单价格；停牌期间累积的信息会体现在跳空里，滑点模型需按「复牌首日放宽滑点」处理。
5. **禁止行为**：不得用 `fillna(method='pad')` 后的价格直接参与收益计算；缺失日的收益应记为 0（持仓市值不变），而不是按填充价计算出的 0% 波动被计入波动率与夏普。

## 4. 时间语义：as-of 规则（最重要）

### 4.1 规则

**策略在时间 T 做决策时，只能访问 `timestamp < T` 的数据；任何 `timestamp >= T` 的数据在 T 时刻都不存在、不可访问。**

这条规则是整个系统可信度的地基。回测里的「未来函数」之所以能造出漂亮曲线，几乎全部源于违反它。

**可执行断言（唯一判定条件）**：

```python
assert (bars["available_at"] <= T).all()
```

`bars` 是策略在决策时刻 `T` 拿到的全部数据。这一句通过，即表示 as-of 规则未被违反；任一 bar 的 `available_at` 晚于 `T` 就失败。`available_at` 的定义见 §4.2。

规则有三层含义：

- **第一层（策略层）**：信号只能由「已完成的 bar」计算，任何滚窗、指标、因子在 T 时刻均不得包含 T 当根 bar 的信息。
- **第二层（数据层）**：查询接口必须支持 `as_of` 参数，物理上截断 `timestamp >= as_of` 的行。策略拿到的 DataFrame 在源头就不含未来数据，而不是靠策略作者自觉。
- **第三层（撮合层）**：成交价必须来自信号产生**之后**的 bar。以 T 时刻的 `close` 生成信号、又以同一个 `close` 成交，等价于用未来数据成交，属于隐性未来函数——即使信号本身只用了历史数据。

### 4.2 bar 时间戳与可用时刻的区别

`timestamp` 是 bar 的**开始时间**（左标签）。日线 `2026-10-23 09:30` 的 bar 覆盖当日全天，它在 `2026-10-23 15:00` 收盘后才完整可用；分钟线 `09:30` 的 bar 覆盖 `09:30–09:31`，在 `09:31` 才完整可用。

因此每根 bar 必须带一个 `available_at` 字段，表示「这根 bar 从何时起可以被策略看到」，它也是 as-of 断言唯一依赖的时间量：

| 频率 | `available_at` |
| --- | --- |
| 日线 | 当日 `15:00`（收盘集合竞价结束） |
| 分钟线 | `timestamp + freq`（如 `14:29` 的 1min bar → `14:30`） |

判定条件：

```
bar 可用 ⟺ bar.available_at <= T
```

注意日线不能用 `timestamp + freq` 推算（`09:30 + 1D` 会跨到次日），必须按上表固定为 `15:00`。

策略在 `T = 2026-10-23 14:30` 时，可以访问 `timestamp <= 14:29` 的分钟 bar（`14:29` 这根在 `14:30` 刚好收完），**不能**访问 `14:30` 这根（它要到 `14:31` 才完整）。

### 4.3 错误示例（使用未来数据）

```python
# ❌ 错误：用当日收盘价算信号，又用同一个收盘价成交
df["ma5"] = df["close"].rolling(5).mean()
df["signal"] = (df["close"] > df["ma5"]).astype(int)

for i in range(len(df)):
    if df["signal"].iloc[i] == 1 and position == 0:
        # 在 bar i 的 close 成交 —— 而 close 正是生成 signal 用到的那个值
        position = buy(price=df["close"].iloc[i], at=df.index[i])
```

问题拆解：

1. `df["close"].iloc[i]` 参与生成 `signal[i]`，又作为 `signal[i]` 的成交价，属于 §4.1 第三层违规。
2. `rolling(5)` 默认右对齐，`ma5[i]` 用到 `close[i]`，天然包含决策时点当根未完成 bar。

```python
# ❌ 错误：整段信号一次性算完，再统一撮合（典型"偷看全表"）
signals = compute_signals(df)          # 在整个 df 上算，隐含用到未来行
for ts, sig in signals.items():
    execute(sig, ts)                   # 撮合时 df 的未来行已在内存里
```

### 4.4 正确示例（严格遵守 as-of）

```python
# ✅ 正确：信号滞后一根 bar，次日开盘撮合
df["ma5"] = df["close"].rolling(5).mean()
raw_signal = (df["close"] > df["ma5"]).astype(int)

# 关键一：信号整体下移一根，决策使用"上一根已完成 bar"的信息
df["signal"] = raw_signal.shift(1).fillna(0).astype(int)

for i in range(1, len(df)):
    # 关键二：决策时点 T = 第 i 根 bar 的开始时间，此时只能看 < T 的数据
    T = df.index[i]
    hist = query_bars(symbol, freq, end=T, adjust="qfq")   # 接口内部强制 timestamp < T

    if df["signal"].iloc[i] == 1 and position == 0:
        # 关键三：用第 i 根 bar 的开盘价成交（决策之后才发生的价格）
        position = buy(price=df["open"].iloc[i], at=T)
```

同类正确写法在分钟线同样适用：`T = 14:30` 时，`query_bars(..., end=T)` 返回的最大 `timestamp` 为 `14:29`。

### 4.5 断言在测试中的写法

```python
def test_as_of_no_lookahead(query_bars):
    T = pd.Timestamp("2026-10-23 14:30")
    bars = query_bars("600519.SH", freq="1min", end=T, adjust="qfq")
    assert (bars["available_at"] <= T).all()
```

- 空表也通过（`all()` 对空序列返回 `True`），不必额外写 `if bars.empty` 分支。
- 日线直接用同一句：`T = 2026-10-23 14:30` 时，当日 `09:30` 那根 bar 的 `available_at` 为 `15:00 > T`，必须查不到，只返回前一交易日及更早的数据。
- 想额外确认「接口确实做了截断」而不是「恰好没数据」，可补 `assert bars.index.max() < T` 作为辅助，但**判定标准仍以 `available_at` 那句为准**。

## 5. 时区

- 全系统统一使用 **`Asia/Shanghai`**（UTC+8，无夏令时）。
- 落盘时 `timestamp` 为**本地时间（naive，不带 tzinfo）**，但其语义固定为 `Asia/Shanghai`；读取后如需与外部系统交互，必须显式 `tz_localize("Asia/Shanghai")`，不得依赖运行机器的默认时区。
- 禁止出现以下写法：
  - 用 `datetime.now()` 生成交易日时间戳（依赖机器时区）；
  - 把 UTC 时间直接当本地时间存入（会产生 8 小时偏移，表现为「日线 bar 落在 01:30」）；
  - 用 `pd.Timestamp.utcnow()` 参与交易日判断。
- 交易日边界以 `Asia/Shanghai` 的 `00:00` 划分；`trade_date` 字段即为该时区下的自然日，用于跨表 join 与分区。
- 服务器、数据库连接、日志时间戳统一配置为 `Asia/Shanghai`，避免排查问题时出现两个时间轴。

## 6. 附：最小校验清单

数据入库与策略上线前，逐条核对：

1. `symbol` 均符合 `代码.交易所` 且为大写。
2. 原始层 `vol` 为「手」、`amount` 为「千元」；经 `to_canonical()` 后 `volume` 为「股」、`amount` 为「元」。用 `amount ÷ volume ≈ close` 抽样自检（见 §1.4）。
3. 价格字段为不复权值；抽查除权日前后，原始价应存在跳空。
4. 停牌日无正常 bar，或占位行 `is_suspended = true` 且价格为 `null`。
5. `query_bars(..., end=T)` 返回值满足 `(bars["available_at"] <= T).all()`（自动测试覆盖）。
6. 全部时间戳按 `Asia/Shanghai` 解释，无 UTC 混入。
